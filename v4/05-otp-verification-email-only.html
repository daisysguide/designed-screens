Same screen handles both Sign Up and Log In OTP flows. Heading is fixed — email is the only OTP channel. Successful verify → Screen 06 Name Entry for new users, Screen 11 Home for returning users.
Backgrounding — new requirement
WhyAn SMS code arrives as a banner and autofills without leaving the app. An emailed code does not: the user switches to Mail or Gmail, reads six digits, and returns. Leaving the app mid-verification is now the normal path, not an edge case.
RequirementEntered digits, the resend countdown, and the error state all survive backgrounding and foregrounding. Returning to the app must not reset the screen or re-trigger a send.
RequirementThe code must remain valid for at least as long as a realistic switch-and-return round trip. Confirm the Supabase OTP expiry window is not tuned to SMS-speed assumptions.
RequirementPaste from clipboard fills all six boxes as one event — the manual equivalent of the autofill that has been removed. Strip whitespace on paste.
Open30s resend lockout was set against SMS delivery. Email delivery is slower and more variable; consider whether the timer should lengthen, or whether "Didn't get it?" should also suggest checking spam.

Behavior notes
Each digit auto-advances focus to the next box. Backspace moves focus back.
No SMS autofill — the code arrives by email. Clipboard paste fills all 6 boxes as a single event; strip whitespace.
Backgrounding to read the code is the normal path. Digits, countdown, and error state all persist across foreground/background.
"Resend code" is disabled for 30 seconds after the screen loads. Countdown pill shows remaining time, disappears at 0.
Wrong code: show error state on all boxes + error message. Don't clear digits. User corrects in place.
Back button and "Go back" both return to Screen 04 Sign Up.
No bottom nav on this screen.
