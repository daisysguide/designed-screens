originating screen
Flow-nav model (reused from Screen 16): presents as a slide-up full-screen modal to 100% coverage, covering the bottom nav. Exits via ✕ top-right or swipe-down-from-top back to the originating screen. The swipe-down gesture is gated: only fires when the content is scrolled to the top and the gesture didn't start on an interactive control (every topic row is interactive here, so this gating matters). No top-left back-a-step — 15 is a summoned editor, not a sequential step in the 16→20 chain. Non-destructive exit; no confirm dialog. In this mock, the ✕ wires to 14-topic-list.html as the demo default; real routing returns to whichever screen summoned it.
Three topic states
✓
Included
Filled purple-500 checkbox · full opacity · topic is in the plan
We hid this
Dashed border · dimmed label · the warm 'we' voice explains why ("We hid this because [reason]. Tap to add back.") · only the initial quiz-filtered state — overwritten by any user action (see provenance flip below)
You hid this
Empty solid border · dimmed label · "You hid this. Tap to add back."
Nothing is ever truly gone — every hidden topic has visible "Tap to add back" text inside its row. Users are always in control.

Includedpurple-500 fill · white ✓ checkmark · 13px bold
We hidWhite bg · 2px dashed border-strong
You hidWhite bg · 2px solid border-default

Provenance flipOnce a user adds back a "We hid" (quiz-filtered) topic and later hides it themselves, the row reads "You hid this. Tap to add back." — not the original "We hid this because [reason]." Most-recent actor owns the label. The quiz reason is only the initial state and is overwritten by any user action. (Underlying provenance can persist server-side; the UI label reflects the current actor.)

Behavior notes
Instant-apply. Every toggle applies immediately and persists; the live count subhead updates in real time. There is nothing to save and nothing to discard — that's why there is no CTA and exit is non-destructive.
Flow-nav modal. 15 presents as a slide-up full-screen modal over the bottom nav. There is no bottom nav inside this screen. ✕ top-right and swipe-down-from-top both exit; the swipe-down is gated (top-of-scroll + non-interactive start) — every topic row is interactive, so the gating actually matters here.
No top-left control. 15 is a summoned editor, not a sequential step in the topic flow, so there is no "back a step" affordance. The ✕ owns exit.
Tap behavior. Tapping a "We hid" topic adds it back as Included. Tapping an Included topic moves it to "You hid". Tapping a "You hid" topic adds it back as Included.
Provenance flip. Once a user touches a quiz-filtered ("We hid") topic and then re-hides it, the row reads "You hid this. Tap to add back." — the warmer "We hid this because [reason]" is gone. Most-recent actor owns the label; the quiz reason is only the initial state.
Flat categories. All 7 categories are always fully expanded. Category headers are static section labels (kept sticky-on-scroll for orientation). There is no collapse / expand. There is no "By category / By stage" grouping toggle — category is the only grouping, by design.
Full-row tap target. The 22×22 checkbox is a visual affordance only (pointer-events: none). The entire row is the hit area, min 44px tall. "Tap to add back" is plain text inside the row, not a separate control.
Exit is non-destructive and resumable. Closing 15 returns the user to whichever screen summoned it (Topic List or Settings). No confirm dialog.
No em dashes in any on-screen copy.
