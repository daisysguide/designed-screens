Key structural decision: answering leads. The guide is supporting, not a required first step, and is offered once here on Topic Intro — there is no persistent mid-question link back to it in v1. No bottom nav — the user is inside the flow.
Flow navigation model

Screen 16 is the entry to the topic flow, so this is where the model is documented. The convention applies to the sequential flow chain (Screen 16 onward), and is also reused by Screen 15 (Manage Topics) as a standalone summoned editor — entered from Topic List or Settings, exits back to its originating screen — rather than a step in the chain.

Enter the flowFrom Topic List (14), the flow slides up from the bottom as a full-screen modal present to 100% coverage. It covers the bottom nav. Inside the flow, there is no bottom nav.
Move within the flowHorizontal push. ‹ top-left or left-edge swipe goes back one screen. The back-a-step affordance appears from the second flow screen onward — Screen 16 has no top-left control.
Exit the flow✕ top-right or swipe-down-from-top slides back down to Topic List. Exit is non-destructive and resumable. No confirm dialog.
Swipe-down gatingOnly fires when content is scrolled to the top and the gesture didn't start on an interactive control.
Direction encodes meaningHorizontal = move within the flow. Vertical = leave the flow.
Reduced motionInstant transitions.
Per-screen exceptionsBack-a-step may be suppressed on specific later screens for state reasons (e.g. Alignment Reveal). Decided per screen, not here.
Partner Status Block (avatar-free variant)

Same component family as the Home / Empty Home Partner Status Block, but stripped of the avatar so it can cap the content group as a centered, content-hugging status chip — not a full-width band that would read as a third button. Home and Empty Home will converge on this avatar-free variant later (their cleanup is a separate follow-up). The pill is promoted to 13px secondary copy from the previous flat 12px tertiary line, so it carries actual weight.

LayoutState-tinted pill · radius-full · 10px / 14px padding · leading icon or status dot · copy · optional trailing chevron. Width hugs its contents (inline-flex, intrinsic width — not width: 100%) so it reads as a status chip, not a third button.
Typography13px DM Sans 600 · 1.3 line-height
No avatar / initial circleAnywhere on this screen, in any state.
Pre-join leading markLeading icon (invite / clock) · trailing › chevron · the affordances together read as actionable / navigational, not as a status badge
Joined leading markLeading status dot · no chevron · informational only, no tap target
PositionCentered in the content column, sitting directly under the blurb as the closing element of the content group (eyebrow → title → blurb → pill), with a small gap above (12px) attaching it to the blurb. The leftover vertical slack lives between the content group and the CTA stack, reading as breathing room above the buttons rather than a gap around the pill. Applies to every state — cyan / gray / neutral turn-states and purple pre-join prompts alike.
Six screen states

Two pre-join states (no partner / invite pending) and four joined turn-states. Pre-join uses generic "your partner" / "they" copy; joined uses the real name (e.g. Jordan). Joined-state tints match the Topic List action-phase pills so the language reads continuously across screens.

Pre-join states are tappable and route to Partner Linking (Screen 10). Answering is allowed pre-link — invite / resend lives in the pill, not the CTA stack. "Ready to reveal" is a real but rare edge case — most users are auto-pushed to Screen 20 when their partner finishes. If they dismissed the push or were offline, the topic sits in this state until they manually tap in. Under prefers-reduced-motion, the glow's breathing animation drops and only the static baseline halo remains.

Behavior notes
No bottom nav. The user is inside a topic flow.
Top-left is empty. Screen 16 is the entry to the flow, so there is no "back a step" affordance here. Back-a-step appears from the second flow screen onward.
✕ top-right and swipe-down-from-top both exit to Topic List. Exit is non-destructive and resumable; no confirm dialog.
Swipe-down is gated: only when content is scrolled to the top and the gesture didn't start on an interactive control.
Reading the guide is optional. From here a user can read the article first or go straight to the questions. In v1 there is no persistent mid-question link back to the article — the article is offered once in the natural flow (Topic Intro → Article → Questions) and each question stands on its own. Cheaply re-addable later as a quiet icon if testing shows people reach for it.
Partner Status Block caps the content group directly under the blurb as a centered, content-hugging status chip — clearly separated from the CTAs by the spacer below so it doesn't read as a third button. Pre-join variants are tappable (route to Screen 10); joined variants are informational.
Ready-to-reveal carries Screen 14's "charge" treatment verbatim: breathing purple glow + always-on baseline halo. Under prefers-reduced-motion, the breathing animation drops; the baseline halo stays.
Layout fits without scrolling on most devices, composed top-to-bottom: 230px illustration · topic eyebrow / title / blurb · centered status pill (caps the content group) · breathing room (via spacer) · CTA stack anchored at the bottom. The remaining vertical slack absorbs between the content group and the CTAs so it reads as breathing room above the buttons; CTAs float to the bottom via spacer, not sticky.
No em dashes in any on-screen copy.
