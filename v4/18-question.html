Four answer types: single-select, multi-select, range-driven slider (shared with onboarding), and ranked-choice. Topics carry 3–5 questions (dynamic N); the step indicator and progress bar template off topic.questions.length. An optional note step follows the last question and submits to Screen 19. Flow chrome: ‹ back-a-step + ✕ exit to Topic List + swipe-down (gated). Demo tabs let you preview each answer type and the linked / unlinked partner state.

Question types — comparison
TypeUsageContinue ruleScoring
single_select (ordered)Sequence: timeframes, amounts, places on a spectrumDisabled until 1 option selected; tapping the selected option deselects itCloseness of the two chosen positions on the sequence — see v4/alignment-logic.md
single_select (unordered)Discrete options with no inherent orderSame as ordered single-selectMatch (1) / no-match (0), with optional partial-credit pairs — see v4/alignment-logic.md
multi_selectNuance questions (several may apply)Disabled until ≥1 option selectedWeighted overlap (shared picks ÷ total distinct picks), per-item weights supported — see v4/alignment-logic.md
sliderIntensity / scale questionsDisabled until the user taps or drags the slider · ghosted thumb is an affordance, not a valueCloseness of the two values, normalized; tolerance band proportional to the question's range — see v4/alignment-logic.md
ranked_choicePriority / preference order questions (e.g. "rank these from most to least important")Enabled on the presented order. No drag is required — the randomized initial order is a valid answer.Rank-similarity (normalized Spearman footrule), position-agnostic, equal weighting by distance moved — see v4/alignment-logic.md
All four types produce a 0–1 score that rolls up to a weighted topic average with the spine question weighted heaviest, mapped to one of three states (Fully aligned · Mostly aligned · Worth a conversation). The weakest-link override can pull a topic down a level even when the average is high. The optional note step is not scored. Presentation order: ranking and unordered single-select / multi-select render their options in randomized order (no implied "right" answer to anchor on); ordered single-select and sliders keep their fixed sequence (the order itself is the signal). Deferral answers (Decide later · Unsure · Haven't thought about it) are tagged so the question always lands in Worth a conversation, even if both partners pick the same one — agreeing to defer isn't alignment. Canonical home: v4/alignment-logic.md.

Ranked choice spec
UIVertical reorderable list of option cards · each row: rank number (left, 20px Grandstander bold, purple-500), option text (center, 15px DM Sans), drag handle (right, ⋮⋮, text-tertiary)
Cardsurface-nested bg · 1px rgba(26,26,26,0.08) border · radius-lg (12px) · 56px min-height · 8px gap between
Drag stateWhite bg · shadow-lg · slight scale-up (1.02) · z-index raised · cursor grabbing
Initial order: randomizedSame spirit as the slider's ghosted thumb — there's no implied "right" ranking to anchor on. The randomization happens per question instance and persists for the user's session.
Rank numbersUpdate live as the user drags. Numbers reflect the current presented order at all times.
Reorder animationSmooth transition (transform 0.2s cubic-bezier(0.4,0,0.2,1)) when an item settles into a new slot. Under prefers-reduced-motion: reduce the transition becomes instant.
Continue ruleEnabled on the presented order. Don't force a drag — the randomized initial order is a valid answer.
Answer storedstring[] of option ids in the user-presented order (rank 1 = index 0)
ScoringRank-similarity (normalized Spearman footrule) — position-agnostic, every position weighted equally by distance moved. Identical orderings score 1.0; reversed score 0.0. Chosen deliberately over a top-weighted variant: two partners who broadly agree on what matters, give or take some ordering, should read as aligned. See v4/alignment-logic.md for the full rule and rationale.

Behavior notes
One question per screen. Never show multiple questions simultaneously.
Never auto-advance on selection. User must explicitly tap the action button. This app is about considered decisions, not quick taps.
N is dynamic. Topics carry 3–5 questions; the step indicator ("Q{i} of {N}") and progress bar both template off topic.questions.length. The screen makes no assumption about a fixed count.
Flow chrome: ‹ back-a-step (left), centered step label, ✕ exit to Topic List (right). Swipe-down from the top of the screen also exits, gated to "scrolled to top + gesture not on an interactive control." No confirm-exit dialog — except mid-way through an unsaved free-text note, which gets a light Save / Discard / Cancel sheet.
Back routing: Q[0] → Topic Intro (16). Q[i>0] → Q[i-1]. Note → Q[n-1].
No mid-question link back to the article in v1. The article is offered in the natural flow on Screen 16 (Topic Intro → Article → Questions) and each question is meant to stand on its own. Cheaply re-addable later as a quiet icon if testing shows people reach for it.
Selection persists if the user taps ‹ back and returns to a question. Answers are saved client-side as the user progresses and committed to the server on Done.
Note step is the final step. Button label is "Done →", not "Continue →" or "Submit →". Always enabled; an empty note is valid and saves as an empty string. The note is shared with the partner and surfaced at the reveal (Screens 20 / 21).
Optional indicator on the note step lives next to the card heading, not on the top bar. The top row stays clean (‹ Note ✕).
Slider reuses the onboarding-quiz component (range-driven by sliderMin/sliderMax; ghosted thumb with border-default border, no fill, no numeric value until first interaction; first tap or drag enables Continue). The component should be promoted to a shared design-system slider so the two screens stay in sync.
Ranked choice renders a reorderable list with rank numbers updating live as the user drags. Initial order is randomized so there's no implied "right" ranking to anchor on, and Continue is enabled on the presented order — no drag is required.
Multi-select questions: Continue becomes active when at least one option is selected.
Partner-name fallback applies to every partner-referencing string on this screen: per-question privacy line, note-step heading, and note-step sub-line. Linked → first name (e.g. "Jordan"); unlinked → "your partner" / "Your partner" (capitalized when sentence-leading).
Per-question privacy reassurance is shown once, on Q1 only ("{Partner} won't see your answer until they've finished too."). Repeating it on every question made it read as boilerplate; one anchored mention does the work.
No bottom nav on any question or note-step screen.
