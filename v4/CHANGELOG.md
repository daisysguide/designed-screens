# v4 changelog

v4 implements the design decisions surfaced during the v3 review. v3 remains
in the repo as the reviewed baseline (no further changes will be made to it).

## Summary of v3 → v4 changes

- **Topic state model:** five states for regular topics (Not started · Your turn · Waiting · Pending · Resolved) plus Locked for prediction cards. Replaces the previous four-state model.
- **Screen 21 redesign:** two reflection options (Resolved · Needs more work), selection required, single "Submit →" CTA. "Talk about it" and "Revisit later" merged into "Needs more work."
- **Snapshot UI cut:** "Original answers" toggle removed from Screen 23. Data retained server-side but not surfaced.
- **Dual view toggle (Category / Stage):** added to Screen 14 (Topic List) and Screen 12 (Progress).
- **Progress screen overhaul:** stacked per-group bars; chaos meter hidden until 3 reveals; alignment % hidden until 5 reveals.
- **Settings additions:** Q1 journey-stage update row in Pacing section.
- **Edit-while-waiting:** "Change my answers" affordance on Screens 19 and 16 Waiting state.
- **Re-answer flow mechanics:** paired round with 14-day expiry; V1.1 will add a unilateral-vs-paired choice.
- **Prediction Cards eligibility:** only shown to users with a future milestone date.
- **No time-gating in V1** except Prediction Cards.
- **Paywall feature list unified** between Screens 09 and 27.
- **Unpaid returning user routing:** Personalized Results → Manage Topics → Paywall.
- **Topic time estimate:** Empty Home shows range ("5–10 minutes"); Topic Intro stats become dynamic per-topic.
- **Visual consistency:** Topics icon 📚 everywhere; partner status "Linked ✓"; American spelling; sample user "Alex"; area code 972.
- **Slider initial state:** ghosted thumb at midpoint instead of fully hidden.

## What's deferred to v1.1 (intentionally out of scope in v4)

- Re-answer flow choice: "update just your answers" vs "start the discussion over"
- Full Q1 update UX with "Rebuilding your plan…" animation and diff screen

- **`v4/alignment-logic.md` added — canonical home for topic scoring + reveal-state rules.** The Screen 18 redesign flagged that the ranked-choice format couldn't ship without its scoring defined and that no alignment-logic doc existed in the repo. This commit lands that doc at `v4/alignment-logic.md` (49 lines, ~6KB). It is the single source of truth for: the four scored input types (slider, single-select, multi-select, ranking) and their five scoring rules (single-select has both ordered and unordered variants); how each rule produces a 0–1 score; the optional free-text note as unscored "fuel for the conversation"; the **spine** concept (one most decision-relevant question per topic, weighted heaviest, led with on the reveal); the **three cross-cutting rules** (deferrals always land in *Worth a conversation* even if both partners pick the same deferral; perspectival "who" questions use absolute *Partner A / Partner B* names rather than *me / you*; presentation order is randomized for ranking and unordered single-select / multi-select but fixed for ordered single-select and sliders, where the sequence itself carries signal); the **weakest-link override** (a single large disagreement can pull the whole topic down a level even when the weighted average is high — "we never let averaging hide a real gap, that gap is the point"); the rollup into three states (**Fully aligned / Mostly aligned / Worth a conversation**) with the spine weighted heaviest; and the **For You Two summary** rule that code decides the alignment and the LLM only writes the words, so the badge and the paragraph can never disagree. Ownership table at the foot of the doc splits Content (questions/options/spine flags/item weights/deferral tags), Engineering (the five scoring rules, deferral and weakest-link logic, partner-name substitution, cached summary generation), and Design/brand (reveal language, three-state framing, summary prompt voice). Slider scoring is range-aware: tolerance band is set proportional to each question's per-question range so a small numeric gap still reads as fully aligned. Ranking scoring chooses the position-agnostic Spearman footrule (equal weighting by distance moved) deliberately over a top-weighted variant — captured in the doc with the rationale so a future "the #1 slot must dominate" decision is recognized as a real formula change, not the current behavior. The doc was sourced from `~/Downloads/daisys-guide-alignment-logic.md` and placed at `v4/alignment-logic.md` (the `daisys-guide-` prefix was dropped because the whole `v4/` directory already lives inside the Daisy's Guide repo).
